# 要求〜高精度機能仕様書 変換スキル (requirements-to-spec)

本スキルは、ユーザーからの曖昧な要望や追加機能のアイデアを受け取った際、直ちにコードを書き始めるのではなく、**「要求分析 → 仕様策定 → 矛盾・リスク検証 → 実装計画」** の 4 段階を経て、手戻りゼロの高品質な仕様書（Spec）を作成するためのプロトコルを定義します。

---

## 🎯 4段階仕様化ワークフロー

1. **Phase 1: 要求ヒアリング ＆ 曖昧さの解消**
   - ユーザーの目的（Why）、対象ユーザー（Who）、解決したい課題（What）を明確化。
2. **Phase 2: 構造化仕様書の作成**
   - 画面設計、データモデル、API 定義、エラーハンドリング、非機能要件を定義。
3. **Phase 3: 矛盾・エッジケース精査（敵対的レビュー）**
   - パフォーマンス劣化、既存機能への副作用、セキュリティリスクを精査。
4. **Phase 4: 実装計画（implementation_plan.md）への落とし込み**
   - タスク分解、影響ファイル一覧、DoD 検証手順を確定。
