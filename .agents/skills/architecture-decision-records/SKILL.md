# アーキテクチャ設計決定記録 (ADR) Skill

本スキルは、プロジェクトの進化過程で「なぜその技術を選んだか」「なぜその設計方式を採用したか」を恒久的に記録し、将来の開発者やAIが仕様迷子になることを防ぐための標準プロトコルを定義します。

---

## 📝 ADR 作成のトリガー（いつ書くべきか？）

以下のいずれかに該当する重要な決定を行った場合、AI は `docs/adr/XXXX_[short-title].md` を作成してください：

1. **データ構造・保存方式の決定:** （例: 通常テーブル + 洗い替え vs マテリアライズドビュー vs イベントソーシング）
2. **キャッシュ・パフォーマンス戦略の選定:** （例: インメモリTTL vs Redis vs HTTP Cache）
3. **認証・セキュリティ方針の決定:** （例: JWT vs セッションCookie、アクセス制限方針）
4. **モジュール・分割アーキテクチャの変更:** （例: ファサードパターンの採用、ドメイン駆動分割）

---

## 📂 保存先と命名規則
- **保存先ディレクトリ:** `docs/adr/`
- **命名規則:** `0001_xxxx_xxxx.md`（4桁連番＋スネークケースの簡潔なタイトル）
- **テンプレート:** `docs/adr/0000_template.md` を複製して使用すること。
